# 科室管理：从列表接口到可操作页面

本次实验已经完成源码开发、真实 MySQL 验证和本机新版本启动。打开 <http://localhost:18082/>，必要时按 Ctrl+F5 强制刷新，即可进入科室管理页面。

## 1. 实现内容与操作入口

| 功能 | 页面操作 | 实际行为 |
| --- | --- | --- |
| 查看列表 | 打开首页或点击“刷新列表” | 查询 MySQL 中的科室，显示总数和刷新时间 |
| 搜索 | 输入名称或编码 | 在已加载列表中筛选，不区分编码大小写 |
| 新增 | 点击“新增科室”，填写表单后保存 | 新记录写入 MySQL，返回数据库生成的 ID |
| 编辑 | 点击对应行的“编辑” | 修改该科室，可保留原编码 |
| 删除 | 点击对应行的“删除”，确认后执行 | 删除指定科室；有关联医生时拒绝删除 |
| 实验接口 | 展开“实验接口与验证入口” | 保留 Hello World、项目信息、数据库及科室 JSON 接口 |

编码以字母开头，只能包含字母、数字和下划线，最多32位；保存时去除两端空白并统一为大写。名称必填，最多64个字符；简介选填，最多255个字符。重复编码返回明确提示。

## 2. 建议按顺序完成的操作演练

1. 打开首页，确认数据库状态为“已连接”，原有内科、外科、儿科正常显示。截取列表全貌。
2. 点击“新增科室”，名称填写“实验心内科”，编码填写“LAB_CARDIO”，简介填写“用于课程操作演练”。如果编码已经存在，使用另一个未占用编码。保存并截图。
3. 刷新浏览器，确认刚才的科室仍然存在，验证数据已经保存到数据库。
4. 在搜索框输入 LAB_CARDIO 或“实验心内科”，确认只显示匹配的记录；清空搜索恢复列表。
5. 点击该测试科室的“编辑”，保持原编码不变，将名称改为“实验心内科（修改）”，更新简介并保存。截图记录。
6. 再次新增，输入同一个编码 lab_cardio 和另一个名称，点击保存。应提示“科室编码已存在”，表单内容保留。点击取消，不新增重复数据。
7. 尝试提交空名称或不符合规则的编码。页面和后端均有输入校验；必填项或编码不符合规则时不能保存。
8. 对刚才自己新建的测试科室点击“删除”，先点“取消”，确认数据仍在；再次点击删除并确认，数据应消失。
9. 刷新浏览器或查询 MySQL，确认测试科室已删除，原有科室未变化。
10. 展开页面下方实验接口入口，复核 Hello World 和数据库检查仍然可用。

如果列表加载失败，页面显示错误提示，并禁用新增。检查项目运行模式和 MySQL 服务后，点击“刷新列表”重试。

## 3. 关联医生的删除保护

程序先检查科室是否关联医生，同时由数据库外键处理并发新增医生的情况；被引用的科室返回 HTTP 409、错误码 40902，科室和医生记录均保留。

此项已通过真实 MySQL 自动化测试：在事务内建立专用测试科室与测试医生，再调用删除接口确认被拦截，测试结束全部回滚。不需要为了演练去改动现有医生资料。

## 4. 接口与分层代码

| 方法与路径 | 成功状态 | 用途 |
| --- | --- | --- |
| GET /api/departments | 200 | 全部科室 |
| GET /api/departments/{id} | 200 | 单条科室 |
| POST /api/departments | 201 | 新增 |
| PUT /api/departments/{id} | 200 | 修改 |
| DELETE /api/departments/{id} | 200 | 删除 |

新增与修改的 JSON：

~~~json
{"code":"LAB_CARDIO","name":"实验心内科","description":"课程演练"}
~~~

| 情况 | HTTP 状态 | 错误码 |
| --- | --- | --- |
| 空名称、非法编码、超长字段、错误 JSON 或 ID | 400 | 40001 |
| 科室不存在 | 404 | 40401 |
| 编码重复（含并发时的数据库唯一约束冲突） | 409 | 40901 |
| 科室已关联医生 | 409 | 40902 |
| 数据库不可用 | 503 | 50301 |

实现链路：

~~~text
index.html + assets/departments.js / departments.css
  → DepartmentController：路由与校验入口
  → DepartmentRequest：输入规范化与 Jakarta Validation
  → DepartmentService：唯一性、存在性、关联检查与事务
  → DepartmentRepository：参数化 SQL、生成主键与查询映射
  → MySQL department / doctor 表
~~~

统一错误处理位于 GlobalExceptionHandler；页面通过 textContent 展示来自数据库的内容，避免将用户输入当作 HTML 执行。本次未更改数据库表结构，未引入新的前端依赖。

## 5. 可重复的自动化验证

在项目根目录打开 PowerShell：

~~~powershell
& .\scripts\Test-Medical.ps1 -WithMySql -Offline
~~~

使用本机加密配置中的应用账号，运行10项测试，其中5项直接验证真实 MySQL。测试创建自己的临时记录并在每个测试结束后事务回滚，不更改原有科室、医生数据。MySQL 自增 ID 可能因测试而出现间隔，这是正常行为。

不加 -WithMySql 时，真实数据库测试跳过，只运行无需连接数据库的测试。缓存不完整时去掉 -Offline。脚本仅执行 test，不覆盖正在运行的 JAR。

本次还执行了页面 JavaScript 的 DOM 环境联调，检查搜索、新增、编辑、删除确认、重复提示和网络恢复，实际请求本地接口并写入专用临时数据，结束后已清理。自动化浏览器受本机权限限制，未完成真实浏览器渲染截图检查；此处不将脚本联调称为完整浏览器测试。

## 6. 修改后的构建与运行

本机当前已运行新版本，无需重新执行此节。以后修改源码时：
